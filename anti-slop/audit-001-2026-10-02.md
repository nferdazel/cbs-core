# Anti-Slop Audit 001 — Frontend CBS Core

Date: 2026-10-02
Scope: `apps/web` (Next.js 15 backoffice)
Mode: Audit (antislop Mode 2). Nothing is modified until specific finding numbers are approved.
Direction: `DESIGN.md` exists and is detailed. Dials declared there: ENERGY 1 / RHYTHM 2 / MOTION 1.

## Verdict in one line

This is an unusually disciplined frontend. Design tokens are enforced, all data views carry three states, accessibility is a real habit (labels, `role="alert"`, `aria-live`, Escape-closable dialogs), there is no fabricated data and no dead-control pattern. The findings below are real but mostly small; only F-02 and F-04 touch user-visible output.

## What passed (evidence, not vibes)

- **Token discipline holds.** Zero inline hex colors and zero non-token Tailwind color classes (grep for `#rrggbb`, `text-gray-*`, `bg-blue-*`, etc. returned nothing outside token classes). All color comes from `globals.css` -> Tailwind `theme.extend`.
- **Three states present.** Shared `States.tsx` (`EmptyState` / `LoadingState` / `ErrorState`), `DataTable` renders loading/error/empty inside the table, and pages fetched data through them. Grep across all 24 dashboard pages found no data page missing state handling.
- **Accessibility is real.** `Input`/`Select`/`DateInput`/`CurrencyInput` all wire `label htmlFor` to `id` via `useId`. `ConfirmDialog` has `role="dialog"`, `aria-modal`, and Escape handling. Error text uses `role="alert"`, async status uses `role="status" aria-live`.
- **Focus is not removed.** Every `focus:outline-none` is paired with a replacement `focus:ring-1 focus:ring-navy-600` (R-32 compliant). Global `:focus-visible` outline defined in `globals.css`.
- **No fabricated content.** No `John Doe`, no `example.com`, no lorem, no invented statistics or testimonials. Placeholder-looking text in settings is honest label text ("Belum tersedia"), not fake data.
- **No dead controls found.** Grep for `href="#"` and empty `onClick` returned nothing. The `FeatureUnavailable` page is the honest alternative to a dead control.
- **Navigation resolves.** Every `nav.ts` entry points to a real route; items are permission-filtered from the server, and unavailable books render an honest "not available" page.
- **Build health.** `tsc --noEmit` clean, `check-i18n.mjs` passes (89 files free of hardcoded user text), ESLint 0 errors.

## Findings

Priority follows the antislop rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Lock = LOW.

### F-01 — Em dash in user-visible strings (HIGH, R-02)

The em dash character `—` appears in rendered output, which R-02 forbids in any text. Three sites:

1. `src/app/(dashboard)/pemetaan-ojk/page.tsx:395` — `` {item.coa_name ? ` — ${item.coa_name}` : ""} ``
2. `src/app/(dashboard)/pemetaan-ojk/page.tsx:426` — `<span className="font-mono">{item.sandi}</span> —{" "}`
3. `src/components/account/AccountOpening.tsx:198, 355, 436` — labels like `` `${selected.cifNumber} — ${selected.fullName}` ``
4. `src/i18n/dictionaries/id.ts:2742` and `en.ts:2747` — "Daftar aset produktif yang telah dihapus buku — kredit maupun..." and the matching English string.
5. `src/i18n/dictionaries/id.ts:2816` and `en.ts:2819` — two em dashes in the "pihak lawan" description.

Fix: replace with comma, colon, or parentheses. For the code/name separators in 1 to 3, a comma or a colon reads naturally; for the dictionary prose, a comma or parentheses.

Note: em dashes appearing in code comments (`operations-types.ts`, `AppSidebar.tsx`, `OJKProfileCard.tsx`, and the rest of the `—` grep hits) are out of scope, R-02 governs user-visible text only.

### F-02 — Nearly duplicated OJK settings cards (MEDIUM, R-14 / C-3)

`components/settings/` holds 21 `OJK*.tsx` cards totalling ~12,600 lines. Each is a register-form card sharing an identical skeleton: same imports (`withCurrent`, `labelOf` helpers are copy-pasted verbatim in `OJKAgunanCard.tsx` and `OJKModalCard.tsx`), same `formFrom`/`emptyForm` pattern, same Card + DataTable + form layout.

This is R-14 territory (identical card shape) but, more importantly, it is C-3 duplication: the layout is correct for the content (these are all "one OJK register form" screens, so uniformity is defensible and matches RHYTHM 2), yet the shared machinery is duplicated 21 times.

This is not a visual slop finding. The cards look right. It is a maintenance finding: `withCurrent`, `labelOf`, and the register-card scaffolding should live in one shared module.

### F-03 — Sidebar nav group headers use wide-tracked uppercase (CLOSED, R-06)

`AppSidebar.tsx:58` uses `text-meta font-medium uppercase tracking-wide text-white/50` for nav group headers.

Verified this is not R-06 slop. The same `text-meta uppercase tracking-wide` pattern is used consistently across ~40 sites (table headers in `DataTable`, `<legend>` in forms, card sub-headings, report section labels) as a secondary hierarchy marker, not as a decorative "technical" heading. R-06 targets uppercase-as-costume for large headings; here it is an established, intentional convention matching RHYTHM 2.

Decision: keep, reason recorded here. Note that `DESIGN.md` is in `.gitignore` (local direction doc, not tracked), so this rationale lives in the audit report rather than in DESIGN.md.

### F-04 — `white/50` and `white/60` text on navy (CLOSED, R-25)

Sidebar group headers (`text-white/50` on `bg-navy-800 #152b47`) and header secondary text (`text-white/60` on the same navy) were verified with the WCAG formula, compositing the alpha over the navy:

- `white/50` over `#152b47` = `rgb(138,149,163)`, ratio **4.70:1** — PASS AA normal text.
- `white/60` over `#152b47` = `rgb(161,170,181)`, ratio **6.08:1** — PASS.

No change needed. Recorded here so the figure is not re-guessed later.

### F-05 — Book scope failure reason builds a sentence from fragments (LOW, R-31 / copy)

`BookScopeGuard.tsx` composes the reason string by concatenating `reasonPrefix + label + reasonMiddle + user?.book_scope + reasonSuffix`. It works and is i18n-friendly, but sentence assembly from six fragments is fragile across languages and hard to read. Low priority; a single parameterized dictionary string with placeholders would be clearer.

### F-06 — Fetch effects without abort/cancellation on two large pages (LOW, code quality)

`AccountOpening.tsx` and `laporan/page.tsx` and `pemetaan-ojk/page.tsx` each carry one `react-hooks/exhaustive-deps` warning. `AppHeader` does use the `cancelled` flag pattern correctly, so the fix is to apply the same pattern. Not an antislop rule, noted because it sits inside the files already flagged.
